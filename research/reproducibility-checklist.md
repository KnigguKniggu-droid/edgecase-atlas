# Reproducibility checklist

## How to use this file

This is a pass or fail gate, not a wish list. Work through it before releasing any result, figure,
table, or claim derived from a run. `reproducibility-manifest.yaml` is the machine-readable record
of the values this checklist asks you to capture. This file says what must be true. That file says
what the values are.

Marking a box requires an artifact a stranger could open. `I remember doing this` is a fail.

Legend for the status column when you copy this into a release record:

- `PASS` with the artifact path or command that establishes it.
- `FAIL` with what is missing.
- `N/A` with the reason it does not apply to this release.

---

## A. Environment and code identity

- [ ] **A1.** The exact repository commit is recorded, and the working tree was clean at run time.
- [ ] **A2.** The Python version is recorded and matches the declared requirement.
- [ ] **A3.** A dependency lock is captured, not just a requirements range. Record its checksum.
- [ ] **A4.** `edgecase_atlas.__version__` at run time is recorded and appears in every certificate.
- [ ] **A5.** The operating system and CPU architecture are recorded, because Z3 and floating-point
      behaviour can differ.
- [ ] **A6.** Every non-default configuration value is captured in a serialized config, not passed
      only on a command line that was not logged.

## B. Determinism

- [ ] **B1.** The root run seed is recorded.
- [ ] **B2.** Seed derivation is documented and reproducible. In this repository, `SeedStreams._seeds`
      derives each stream by SHA-256 over `edgecase-atlas:<root>:<stream>:<index>`.
- [ ] **B3.** Search, gate, shrink, and held-out streams are proven pairwise disjoint by an automated
      test, and the test node id is recorded.
- [ ] **B4.** Running the same command twice with the same seed produces the same run identifier,
      the same certificate identifiers, and the same charged-call totals. Both runs are retained.
- [ ] **B5.** Any nondeterminism that survives is named explicitly, with its source. A target that
      ignores the seed parameter is the expected case and must be stated, not assumed away.
- [ ] **B6.** Wall-clock timing and latency fields are excluded from every content digest, so timing
      variation cannot change an identifier.

## C. Target identity

- [ ] **C1.** The target model identifier is recorded.
- [ ] **C2.** The adapter kind is recorded (in-process function, subprocess, or HTTP endpoint).
- [ ] **C3.** The prompt is captured by digest, and the prompt text is archived where licensing
      permits.
- [ ] **C4.** Decoding parameters are recorded, including temperature, top-p, token cap, and stop
      conditions.
- [ ] **C5.** Quantization, weight hash, or provider build identifier is recorded where the target
      exposes one, and its absence is recorded where it does not.
- [ ] **C6.** The reset protocol between arms is documented and was executed.
- [ ] **C7.** The adapter configuration hash in the certificates matches the recorded configuration,
      and no secret was included in the hashed material.

## D. Data

- [ ] **D1.** Every input dataset has a path, record count, and SHA-256 recorded.
- [ ] **D2.** Each checksum was recomputed at release time, not copied from a previous document.
- [ ] **D3.** Datasets generated by code can be regenerated from that code, and the regenerated file
      matches the recorded checksum byte for byte.
- [ ] **D4.** The license of every dataset is recorded, and third-party material is not relicensed.
- [ ] **D5.** The partition split is group-level, was applied before any target execution, and its
      manifest is archived.
- [ ] **D6.** Development and pilot data are provably excluded from confirmatory outcomes.
- [ ] **D7.** A privacy review was run over any non-synthetic source. The structural provenance guard
      in `models.Provenance` is documented as incomplete and does not count as the review.

## E. Accounting

- [ ] **E1.** Every attempted target call is charged exactly once, including timeouts, crashes,
      malformed outputs, and retries.
- [ ] **E2.** Per-phase counts reconcile against the raw event stream, with no unexplained residual.
- [ ] **E3.** Generator calls are accounted separately from target calls and are not conflated.
- [ ] **E4.** Planning figures are never reported as realized totals. Any headline call count states
      whether it is a search-only allocation or a complete charged total.
- [ ] **E5.** Unknown cost estimates serialize as unavailable, not as zero dollars.
- [ ] **E6.** Wall time, token counts, invalid proposals, repair attempts, and cost-cap failures are
      present in the ledger.

## F. Analysis

- [ ] **F1.** The analysis code is in the repository, is version-controlled, and its checksum is
      recorded alongside the results.
- [ ] **F2.** Every reported statistic can be regenerated from the archived event stream by a single
      documented command.
- [ ] **F3.** Randomized or bootstrap procedures record their seed, and rerunning reproduces the
      reported interval exactly.
- [ ] **F4.** The multiplicity correction covers exactly the p-values declared in the preregistration
      and no others.
- [ ] **F5.** Exploratory analyses are labelled exploratory in every table and figure caption.
- [ ] **F6.** Excluded records are counted and reported by arm. A silent drop is a fail.

## G. Artifacts and claims

- [ ] **G1.** One machine-readable certificate exists per reported violation.
- [ ] **G2.** Each certificate's content digest recomputes to its own identifier.
- [ ] **G3.** Each certificate's replay command was executed against the archived environment and
      reproduced its recorded outcome, or the discrepancy is documented.
- [ ] **G4.** Every claim in the write-up has a row in `evidence-ledger.md` with a status other than
      `Not produced`.
- [ ] **G5.** No claim of safety, certification, real-world validation, or vehicle suitability
      appears anywhere in the release.
- [ ] **G6.** No number in the write-up lacks a derivation path to an archived artifact.
- [ ] **G7.** No personal name, institution, mentor, email address, or local filesystem path appears
      in any released artifact.

## H. Deviations

- [ ] **H1.** A deviation log exists and covers the period from freeze to release.
- [ ] **H2.** Each deviation records what changed, why, and whether the affected analysis is now
      exploratory.
- [ ] **H3.** No section of the frozen preregistration was edited in place. Changes are appends.

## Known reproducibility limits in the current alpha

Recorded here so they are not rediscovered as surprises. Each is traced in `evidence-ledger.md`.

- Held-out confirmation seeds are derived but never consumed by the engine, so no run in the alpha
  can satisfy the `research_confirmed` rule that `research/analysis.py` enforces.
- The engine and minimizer pass the trial count and required reproductions as literals rather than
  reading the exported constants, so changing a constant changes certificate identity without
  changing behaviour.
- The four non-Atlas benchmark method identifiers are accepted by the evidence validator but have no
  search implementation, so no comparative result is currently producible.
- Targets that ignore the seed argument make B4 hold for the engine while the target's own outputs
  vary. In that case B5 must name the target as the nondeterminism source.
